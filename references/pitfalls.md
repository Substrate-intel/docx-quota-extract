# 踩坑清单（sz05 全书 + 会话全程实战沉淀）

> 新卷开工前通读本清单；遇同类症状按「根因」列 grep 定位。铁律：疑点留痕不静默，任何一处踩坑复发都是门控红。

## 一、docx 结构类（保真层/目录）

### 坑 1｜w:sdt 内容控件整块跳过 —— 目录全丢
- **症状**：整卷目录提取不到（只剩目录区外零星行）。
- **根因**：Word 目录/自动编号内容包在 `w:sdt` 结构化文档标签内；python-docx 的 `iter_block_items` 只迭代 body 直接子元素（`w:p`/`w:tbl`），`w:sdt` 里的段落全部不可见。
- **根治**：不修 python-docx，直接正则解析 `document.xml` 段落流：按 `<w:p` 切段，每段串联全部 `<w:t>` 文本，穿透 sdt。见 `scripts/parse_desc.py` 目录段。
- **教训**：保真层"全量"的验证必须包含"目录区可见性"检查——用目录行数（章行/节行/子目行计数）对账，不要只看总块数。

### 坑 2｜孤儿页码行 —— 目录项拆两段
- **症状**：个别目录项 title 为空、页码自成一条记录。
- **根因**：源 docx 个别目录项「5.套环柔性接口」与「(214)」被拆成两个段落。
- **根治**：纯页码行 `^\(\d+\)$` 回填前一条记录的页码，并重排序号。

### 坑 3｜附表锚点命中目录行 —— 取错表
- **症状**：材料预算价格取定表 16 张全部对不上。
- **根因**：目录里也有「材料预算价格取定表……(809)」（带省略号+页码），`next()` 从头扫正文段落时命中目录行，锚点取到子目表。
- **根治**：精确纯表题匹配（`text.strip() == '材料预算价格取定表'`）且取**最后一个**命中段（`max()`），因为目录在正文前。

## 二、子目解析类

### 坑 4｜费用行误判覆盖材料费 ——「其他材料费（元）」
- **症状**：部分子目材料费被「其他材料费」行覆盖成极小值。
- **根因」：行首字「其」开头的行被统一判为费用行（其他材料费是综合费类费用行），但它实际是材料消耗行。
- **根治**：行首字分类（基=基价、其=其他费用→费用行；人/材/机=消耗行）+ `not in_cons` 门控（已在消耗行上下文中时不再切换）。

### 坑 5｜续前表无表头行 —— 消耗行整批丢
- **症状**：跨页续表的子目材料行缺失。
- **根因**：续前表省略「名称/消耗」表头行，表头开关式状态机未开启导致整批行跳过。
- **根治**：弃用表头开关，统一行首字判定分类。

### 坑 6｜机械规格数字核污染 ——「10m3/min」变「103」
- **症状**：机械规格字符串中的数字被朴素抽取成 `103`，撞错价格档。
- **根治**：规格匹配三级策略——全数字串精确匹配 → 前导整数匹配 → 唯一前缀匹配；含单位字母的数字禁直抽。

### 坑 7｜单位沿用串表 ——「10 根」串成「100m」
- **症状**：个别子目单位错误（跨表沿用上下文污染）。
- **根治**：单位正则放宽 + 沿用仅限续前链内（新表/新组不沿用）。

### 坑 8｜「同前」级联展开静默失效
- **症状**：书印「同前。」承接的子目工作内容为空。
- **根因」：同前清洗正则只去「工作内容:」前缀，未去「计量单位:」后缀——前置条目文本尾部带计量单位后缀时匹配失败。
- **根治**：`_cw_()` 同时去前缀+后缀：`re.sub(r'^工作内容\s*[:：]', '', s)` + `re.sub(r'计量单位\s*[:：].*$', '', s2)`。

### 坑 9｜组首工作内容隔表不可达
- **症状**：35 条工作内容缺失。
- **根因**：回溯遇表格即停（工作内容段与子目表之间隔了别的表）。
- **根治**：三刀——①跳表回溯（跳过中间表+续前段，遇工作内容即取，节标题停）②排表后形态③同前级联展开。终态：空 0 / 同前残留 0 / 回填 0（提取器完全自给）。

## 三、索引/条文类

### 坑 10｜rules 区混入节标题
- **症状**：ch1 计算规则 41 条中 22 条是节标题。
- **根因」：rules 扫描区未止于首个节标题。
- **根治**：rules 区止于 `sections[0].blk`。

### 坑 11｜子目标题与「工作内容」粘连 → 漏采
- **症状**：正文索引比目录少 4 条子目。
- **根因」：个别子目标题段与「工作内容:…」连成一段，超长度过滤被丢。
- **根治」：`t_sub = re.split(r'工作内容\s*[:：]', t)[0]`，去空白计长 ≤30；**目录层反证救回**（目录 179 = 正文 179 全等）。

### 坑 12｜条款切分粒度不一致（对齐 PDF 版前）
- **症状**：docx 版 113 条 ≠ PDF 版 152 条。
- **根因」：docx 按章把子项并入父条；PDF 版父条与子项各自单列（向量索引粒度）。
- **根治」：用户裁定后以 **PDF 库 sections 为骨架**一一同构对齐，docx 原文做字符级切片留痕。

## 四、对齐层类

### 坑 13｜norm 下标当链下标 —— 切片整体漂移（最隐蔽）
- **症状**：01-SM-21 切片起点从 `8.` 错位到 `、机械乘以系数 1.3。`；前段无空白的条碰巧不错位。
- **根因」：`chain_slice` 收的是 norm 字符串下标，却当链数组下标用——空白/删除字符在 norm 中被吃掉，两坐标系错位且随位置累积。
- **根治」：`norm_index_map(chain)` 建立 norm 字符 → 链下标的严格映射，所有切片经映射转换。
- **教训」：双坐标系（规整串/原文链）之间必须有显式映射，任何"长度差不多"的巧合对齐都是假象。

### 坑 14｜字形/全半角噪声 —— 差异格假阳性
- **症状**：对账大量"差异"格实为噪声。
- **归一集（定版）**：全角标点→半角（，：；！（））、`²→2 ³→3 ¹→1`、`×(U+00D7)→x ✕(U+2715)→x`、`∶(U+2236)→:`（配比符号 30∶70、1∶2.5）、`ϕ/φ→φ`、全角引号删除、去空白。
- **permute 判定**：PDF 双列字符交错提取（如「镀锌六角螺栓带螺母$2平垫1弹垫 M16×100以内」）与 docx 正序做**字符多重集（sorted）相等**→判定提取序差非内容差，留痕不静默。

### 坑 15｜表体拍平格式差异 —— 双尾巴留痕
- **症状**：5 条 table_flat_diff。
- **根因」：PDF 把内嵌表直拼进条文文本；docx 版有「〔内嵌表〕」标记+结构化表。
- **根治」：引子前缀贪心匹配 + docx/PDF 双尾巴留痕（desc_align_log.json）；docx 独有表文本进 `desc_docx_extra` 表。

## 五、核验/门控类

### 坑 16｜H1 None 处理不一致
- **症状**：恒等式核验忽跳忽算。
- **根治」：统一 `(l or 0) + (m or 0) + ...`，禁把 None 当 0 跳过或混用两种口径。

### 坑 17｜P1 页码偏移与编码粘连
- **症状**：P1 取证误杀。
- **根治」：页码 **1 起算** `doc[p-1]`（库 page 口径）；编码判定用原始文本数字边界 `(?<!\d)5-\s*N(?!\d)`，防「5-15-2」粘连误杀。

### 坑 18｜基线指纹刷早/刷晚
- **症状**：门8 恒红或基线掩盖缺陷。
- **铁律」：有意变更后 → 确认门1-7/9 全绿 → `gate.py --make-manifest` 刷指纹 → 复核；**末章 summary 写盘必须在基线刷新之前**。门8 失配文件必须逐个确认是有意变更产物，不可一把刷过。

### 坑 19｜前端冒烟照搬他卷锚点 = 没跑
- **症状**：冒烟全绿但视图空白。
- **根因」：PDF 版锚点（GS 三档、「总说明」类型）在安装/docx 卷不存在（「册说明」/labor_tiers=null）。
- **根治」：分卷适配——读 DATA.meta 动态生成 + null 安全降级 + 每卷写专属冒烟锚点集。

### 坑 20｜费率降效表硬造子目
- **症状**：书本身无基价行的费率表（人工/机械降效、操作高度增加费等）。
- **正确行为**：**不硬造子目**，high issue 留痕；费率章 0 子目合法（check 加 _fee_only 例外）。

### 坑 21｜目录 sdt 半泄漏污染章锚（sz01 实证）
- **症状**：章锚数量 > 正文章数，章区间错乱（sz01 泄漏 4 章行，sz05 是全 sdt 零泄漏——两种形态都会踩）。
- **根因」：w:sdt 内容控件包裹不完整，部分目录行漏成真实 body 块；章锚正则按全文扫误收。
- **根治」：正文章锚只取「册说明标题块（`^册\s*说\s*明$` 精确匹配）之后」的章行——册说明标题在目录之后是卷结构不变量。
- **验证」：sz01 八章锚点全部落正文位置（TOC 泄漏行 4 条被过滤）。

### 坑 22｜附录区无「条首」走不进 clause_records
- **症状**：附表记录数=0，附录段全进 leftovers。
- **根因」：附录区是「标题段+表题段+表格」无「一、」条首，clause_records 的 cur 恒为 None。
- **根治**：附录区整段显式成条（id=`{册码}-FB-01`，text=标题段拼接，tables=全表 flatten），页码经目录「附录条目行」印刷页锚定（坑 ㉘：查 level='附录条目行' 不是 ref_kind='附录条目'）。
- **验证」：sz01 附表 1 条、10 行全格非空、print_page='119'/page=132。

### 坑 23｜无 PDF 对照库时 P1 取证页映射内建法
- **症状**：P1 依赖 PDF 库 items.page 页映射，docx-only 卷（无 PDF 提取库）无法启用。
- **根治**：页映射内建——对每子目用 `(?<!\d){册前缀}-\s*N(?!\d)` 扫全 PDF 原文页 + 基价字符串 norm 命中同页，取首中页为该子目物理页；映射存 cost_check_report.P1_pages/P1_print_pages 供前端与门9b 复用。
- **验证**：sz01 258/258 全命中；门9b 硬锚点「TOC 首节行印刷页 == P1 库该章 min(print_page)」8/8 精确命中（17/37/51/59/89/105/109/115）。

### 坑 24｜portal 现查制不认 docx 卷
- **症状**：build_portal.py collect_quota 依赖 PDF 版 schema（chapters/sections/extraction_issues 表、web/index.html），docx 卷注册即 KeyError。
- **根治**：新增 kind='docx_quota' 分支（库/前端/基线全部 docx_source 化：docx_quota.db、index.html、manifest.json、cost_check_report.json）+ render_registry 前端链接按 kind 分流 + 尾部汇总 print 按 kind 分支。
- **验证**：sz01 注册后 portal 现查渲染 items=258/desc=57/P1=258/baseline=11，官清对照「已识别」状态正确联动。

## 六、md 源管线变体（lvse·绿色建筑卷实证，2026-10-15，坑 25-33）

> 适用「有官方无水印 PDF、无 docx 源」的卷。链路与参数见 `scripts/md_source/README.md`。

### 坑 25｜转换层三连：pymupdf4llm 段错误 / 旋转水印 redact 整页抹除 / E-BZ 小数空格
- **症状**：① `import pymupdf4llm` 即段错误（exit 139，1.28.2 布局引擎本机崩溃）；② 对 ~40° 旋转水印行 bbox 做 redact → 整页内容被抹（输出塌缩）；③ 「1228. 26」带空格小数。
- **根因**：① pymupdf4llm 布局引擎 C 库与环境冲突（pymupdf 本体不受影响，基线安全）；② 旋转文本的 bbox 是旋转外接矩形，轴对齐化后罩住全页；③ E-BZ 西文字体数字间距。
- **根治**：转换层用裸 fitz 自研（字号分级 H1/H2/正文/定额表 + `find_tables()`→md 表）；水印**不 redact**，改单元格级行首孤立 token 剔除 `^([水印字符集])\s`——行首锚定防「基价」等双面字误伤；小数归一 `(\d)\.\s+(\d)→\1.\2`。
- **验证**：绿色建筑卷 269 页全转（H1×6/H2×13/表行 3888/页锚 258），md 285KB 字节级可复现。

### 坑 26｜E-BZ 页码散字：单字符行 + 外侧边位置 + 分区 offset
- **症状**：页码提取 0 命中或数字乱序（'942'≠'249'）。
- **根因**：E-BZ 基线下沉致页码每字符独立成行（`·`/数字/`·`）；位置在**外侧边**（偶页左 x≈50、奇页右 x≈510），居中假设错误；目录区与正文区 offset 不同。
- **根治**：y 345-372 + x<100 或 x>470 收集散字，**按 x 左→右重组**（reverse 排序=数字倒序坑）；页码口径分区标定（lvse：正文 P10-269 offset +9，目录区 P6-9 offset +5，P1-5 与章扉页对无印刷页码）。
- **验证**：页锚 258/269；无页码扉页对（12/13、66/67、206/207、226/227、256/257）正确排除。

### 坑 27｜md 章标题 `# ` 前缀剥离 → startswith("#") 边界静默全失效
- **症状**：册说明 buf 吞掉 848 段落；所有 `startswith("#")` 检查静默失效（不报错、产物悄悄错）。
- **根因**：extract_md 产块时剥掉 md 标题的 `# ` 前缀存 text，下游沿用文本前缀判界。
- **根治**：块结构显式 `kind: "h1"/"h2"`，**全部边界检查改 kind 判定**（禁文本前缀判界）。
- **验证**：册说明段落收敛 396→62→9（终态），章节区间全对。

### 坑 28｜md 合并单元格形态 ≠ docx 纵向合并：行判别三法
- **症状**：消耗行 kind 链断裂（md 合并单元格=**首行有值后续空**，docx 纵向合并=每行重复值）；独立名称行（c0 空、名称在 r[3:]）与消耗行混淆；跨列合并标签留空。
- **根治**：① 消耗行=前 kind 链式承接（c0 空）；② 名称行=r[1] 无值 + r[3:] 非数字文本；③ 跨列标签 `hfill_label` 横向填充；**单项子目表费用行**（费用名在 r[1]）用 `"(元)" in joined` 检测；规格/档位行 ci_value_check 放行（纯数字/每增减N/≤N）。
- **验证**：487 子目 parse_issues=0；item_materials 2919 / item_machines 652 全分类。

### 坑 29｜工作内容/计量单位拆行 → 双遍扫描
- **症状**：430 子目 unit 空（单遍扫到「工作内容」行即 break，到不了「计量单位」行）。
- **根因**：docx 版两者同段，md 版拆成独立两行，单遍状态机被先出现的行截断。
- **根治**：unit/work **各扫一遍**；边界=h1/h2 kind + 节标题正则；分号结尾的「N.」子行是工作内容延续**不 break**（坑 11 的 md 形态）。
- **验证**：unit 空=0、work 空=0（门3 全绿）。

### 坑 30｜节标题折行污染 sections → 跟表验证
- **症状**：sections 32 个 vs 目录权威 14 个（说明区长标题折行后恰命中节标题正则）。
- **根治**：节标题判定加**跟表验证**——其后 6 块内须有表格（说明区折行后跟段落非表）；窗口必须 6 块（4 块漏表距 5 块的案例）。
- **验证**：sections 14/14 与目录节行集合全等（门6）。

### 坑 31｜目录双栏重组（不经 md）
- **症状**：目录行错配/丢行/页码错挂。
- **根因**：双栏排版 PDF 全文序输出左右栏交错；md 表格化又破坏坐标。
- **根治**：从 nowm.pdf 目录页 dict 直接重建——x<280 左栏 / ≥280 右栏分流 + 栏内 y±6.5 聚类 + 长标题与页码行合并；页码字符坐标是唯一权威。
- **验证**：77 行（章4/说明4/规则4/节14/子目49/附表1），与正文集合全等、页码单调（门6）。

### 坑 32｜H1 恒等式项数因卷而异（四项制）
- **症状**：H1 全卷 fail（lvse 曾 487/487 红）。
- **根因**：沿用三项式（基价=人+材+机），本卷及 sz05 实为**四项制含综合费**（sz05 5-1: 3277.47=1767.05+17.27+995.83+497.32）。
- **根治**：H1 公式**开工前用已知好卷样例校准**再放大；「—」费项按 0 计并留痕。
- **验证**：H1 487/487 pass（299 条「—」计 0 留痕）；H2 费率带宽按卷实测（lvse 统一 ~15.2% → 带宽 0-0.16）。

### 坑 33｜P1 灵活正则必须作用于未去空白原文
- **症状**：P1 44/487 fail——去空白后相邻编码粘连 '20-920-10'，lookbehind 误杀。
- **根因**：页文本 strip 后相邻子目编码拼接；E-BZ 数字间距又被随机空格拆开——两个方向同时破坏正则。
- **根治**：正则作用于**原始未去空白**页文本：编码 `(?<!\d)20-\s*N(?!\d)`、基价 `120[\s.]*78`（E-BZ 空格容忍）。
- **验证**：P1 487/487（对**官方带水印原版**取证——提取用 nowm 干净源、校验用官方原版，双源口径）。

### 坑 34｜前端契约错配致「加载中」假死 + 冒烟必须渲染级（lvse 实证）
- **症状**：成果库首页永远「加载中…」；文件存在、大小正常、门控全绿（基线当时锚的就是错配版）。
- **根因**：两级——①build_front 产出 **docx 短键契约** DATA（items: c/ch/n/u…、无 stats/sections/toc），而 PDF 版 template.html 渲染链吃 **PDF 长键契约**（头部 IIFE `DATA.stats.h` 与 `DATA.sections.some` 相继 TypeError，script 整体崩溃，main 永不替换）；②冒烟只验「文件存在/大小/DATA 可解析」，未执行渲染——坑 19「冒烟必须分卷适配」的高阶形态：**分卷适配了锚点但没执行启动链**。
- **根治**：①前端构建按 sz05 docx 版 `build_docx_front_pdf_style.py` 的**成熟契约映射**写（stats/sections/toc/items 长键/details/validate/nodes/REVIEW 两源全套），卷适配点显式替换（itemPrefix 硬编码章码推导→读 `DATA.meta.code_prefix`；节印页 `-27`→`-DATA.meta.offset`）；②**渲染级冒烟机械化**：node + 最小 DOM stub 执行内联脚本（`smoke_front_lvse.mjs`），断言启动链零异常 + main 非「加载中」+ 13 个视图路由逐一真跑。
- **验证**：lvse v2 重建后冒烟 22/22 全绿；端到端重跑字节级一致（sha 前后相同）；门控 8 绿→刷指纹→九门 9/9。
- **纪律**：前端交付的完成态=**渲染级冒烟全绿**，不是文件产出；门控基线只锚定「可复现」，不锚定「可渲染」。

## 七、流程纪律（管理类）

- **校核≠重做**：核验只交付取证+缺陷清单，修复是独立门控工序。
- **每轮先验证上轮数据**：下一批任务前必须核对上一轮数据准确性。
- **subprocess 三件套**：`capture_output + stdin=DEVNULL + timeout`，防交互式挂死。
- **确定性三禁**：禁运行时时间戳、禁静默修正、禁丢弃残余（全部留痕+对账）。
- **端到端验证**：本地绿测不算完成，全链重跑字节级复现才算收官。
